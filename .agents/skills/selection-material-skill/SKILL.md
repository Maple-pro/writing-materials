# 遴选官媒素材整理 Skill

## 目标

把“每天阅读官媒”转化为可长期复用、可在遴选考场快速调用的知识系统，而不是文章收藏夹。

工作闭环：

`官媒文章 → 快速筛选 → 精读拆解 → 文章卡 → 专题库/素材库 → 每周主题输出 → 真题训练 → 知识缺口 → 反向指导阅读`

核心原则：**AI 做机械整理，人做认知加工。** 不替用户完成本应由用户训练的判断、概括和答题转化。

### 专题库组织规则：三级截止原则

专题库采用“一级领域文件夹 → 二级专题 Markdown → 三级知识点标题”的固定结构。

1. **一级领域 = 文件夹**：使用上面的 12 个稳定领域，只做粗粒度分类。除非长期出现无法归类的重要领域，否则不要新增一级目录。
2. **二级专题 = Markdown 文件**：只有能够独立形成遴选命题、且已有或预计会持续积累内容的主题，才创建独立 Markdown，例如 `基层治理.md`、`基层减负.md`、`科技成果转化.md`。
3. **三级知识点 = Markdown 内标题**：更细的概念使用 `##` / `###` 组织，例如“权责不匹配”“中试环节薄弱”，不要继续拆成文件。
4. **第四级及跨领域关系 = 双向链接**：不要继续建立目录层级，通过 `[[专题名]]` 表达交叉关系。文件夹只负责粗分类，链接负责知识网络。

核心判断：**先有内容，再建专题；不要预先批量创建空 Markdown。**

#### 新建二级专题的判断门槛

新建专题文件前必须先搜索已有专题，并依次判断：

- 该内容能否独立形成一道遴选题，例如“分析当前科技成果转化存在的问题并提出对策”？
- 是否已经具有至少两个以上可持续积累的维度，例如核心认识 + 问题/原因/对策中的两个以上？
- 是否不是现有专题下的一个普通知识点？
- 是否预计会被后续文章持续更新，而不是单篇文章中的一次性概念？

满足上述条件时可以新建；否则先写入最接近的已有专题，作为 `##` 或 `###` 知识点。随着内容增长，再执行“专题升级”。

#### 专题升级

当某个三级知识点逐渐具备独立命题价值，并已经形成较完整的“核心认识—问题—原因—对策”等内容时：

1. 新建对应二级专题 Markdown；
2. 将原专题中的详细内容迁移到新专题；
3. 原位置只保留简短概括和 `[[新专题]]` 链接；
4. 修复相关双向链接；
5. 避免新旧两处长期保存重复正文。

- 基层治理与社会治理：基层治理、社区治理、基层减负、数字治理、党建引领基层治理、群众工作、多元共治。

## 三个长期库的职责

### 专题库：知道什么

按考试主题组织，例如基层治理、科技创新、高质量发展、乡村振兴、干部队伍建设。保存核心认识、问题、原因、对策以及指向素材库的链接。

**更新频率：高。** 每次完成有价值的精读后都检查是否存在专题增量。

### 素材库：能拿什么来用

保存具有跨题目复用价值的独立资产，例如典型案例、权威数据、政策表述、真正值得记忆的表达和小标题。

**更新频率：中。** 只有达到准入标准才新增，禁止把每个摘抄都变成素材。

### 方法库：怎么分析、怎么写

保存跨主题仍然成立的分析方法、答题结构、公文写作方法、大作文论证方法。

**更新频率：低。** 主要由每周复盘和真题训练产生，不因单篇文章轻易新增方法。

## 工作模式

根据用户指令选择以下模式。若用户只给文章并要求“整理/精读/沉淀”，使用“每日精读模式”。

### 模式 A：每日文章筛选

适用于当天有多篇推荐文章。

1. 阅读文章标题、来源、日期、摘要/正文。
2. 按遴选价值判断：政策相关性、观点密度、结构价值、案例价值、表达价值、与现有知识库的互补性。
3. 推荐精读 2–3 篇即可；其余可标记“浏览/跳过”。
4. 不做政治立场评价，不对政治人物或政策做支持/反对式判断；只提取公开材料中的事实、政策表述、论证结构和考试用途。

输出简洁的筛选结果与理由，不直接把所有文章写入长期库。

### 模式 B：每日精读与沉淀

#### 第一步：建立文章卡

路径建议：`00-每日阅读/YYYY-MM-DD-短标题.md`

模板：

```markdown

- 来源：
- 日期：
- 原文：
- 主题：
- 状态：已精读

## 一句话主旨
> [AI候选，等待用户确认/修改]

## 文章结构
- 背景：
- 问题：
- 原因：
- 对策：
- 升华：

## 可迁移观点
- 

## 素材候选
### 案例
- 
### 数据
- 
### 权威表述
- 
### 表达/小标题
- 

## 我的转化
> [用户填写：如果考场出现相关题目，我会如何组织成自己的观点/分论点/对策？]

## 关联专题
- [[专题名]]

## 沉淀记录
- 专题库：
- 素材库：
- 暂不沉淀：
```

注意：AI 可以给“一句话主旨”和“我的转化”的候选提示，但**默认不要替用户填写最终版“我的转化”**。保留明显占位，要求用户亲自完成或确认。

#### 第二步：更新专题库

先搜索已有专题，避免重复创建同义专题。

把文章中真正新增的内容合并到对应专题。先判断应当“更新已有专题”“在已有专题内新增三级知识点”还是“创建新的二级专题”，不得看到新概念就新建文件。专题统一使用：

```markdown
# 专题名

## 一、核心认识

## 二、现实意义

## 三、主要问题

## 四、原因分析
### 思想
### 制度
### 机制
### 资源
### 能力
### 作风

## 五、对策措施

## 六、关系辨析

## 七、可调用素材
### 案例
### 数据
### 权威表述

## 八、可用表达

## 九、关联专题

## 十、知识缺口
```

模板栏目允许为空；不要为了填满模板而制造内容。对于不适用的专题，也可以省略明显不适用的子项。

规则：
- 已存在的同义观点不重复追加；优先合并、精炼。
- 新观点必须能脱离原文成立，不能保留大量上下文依赖。
- 文章中的普通事实/观点优先留在专题库，不要全部独立建素材卡。
- 专题库引用素材库，避免复制完整素材。
- 一个专题原则上只属于一个一级领域文件夹；若同时涉及其他领域，通过 `[[双向链接]]` 关联，不复制专题文件。
- 若无法判断新概念是否值得独立成专题，默认不新建文件，先作为已有专题中的三级知识点沉淀。

#### 第三步：筛选素材库候选

素材独立入库至少满足以下一项：
1. 能用于 2–3 个以上主题；
2. 是具有代表性的具体案例；
3. 是权威、稳定且有明确来源的数据；
4. 是值得记忆且有明确来源的权威表述；
5. 是具有明显迁移价值的表达或小标题。

不满足则留在文章卡或专题库。

案例卡模板：

```markdown
# 案例名称

## 核心事实

## 能说明什么

## 适用主题
- [[专题A]]
- [[专题B]]

## 考场使用方式

## 来源
- 
```

对于数据，必须保留**时间、统计口径、适用范围和来源**，不得把历史数据写成当前事实。

#### 第四步：输出变更摘要

每次实际写入后告诉用户：
- 新建/更新了哪些文章卡；
- 哪些专题增加了什么；
- 哪些素材独立入库以及原因；
- 哪些候选没有入库以及原因；
- 哪一部分需要用户完成“我的转化”。

### 模式 C：每周主题重组

每周重组不是“总结本周读过哪些文章”，而是把已有知识重新组织成考试答案。

1. 从本周高频主题或用户指定主题选择一道题。
2. 首先创建闭卷区，提醒用户先自行填写。AI 不要直接覆盖用户的闭卷答案。
3. 用户完成后，再读取专题库和素材库进行对照。
4. 找出遗漏观点、原因、案例、数据和表达。
5. 形成“最终答题框架”和“下周重点收集”。

路径：`04-输出训练/每周主题输出/YYYY-Www-主题.md`

模板：

```markdown
# YYYY-Www 每周主题输出：主题

## 本周闭卷题目

## 我的核心判断（闭卷）

## 我的闭卷框架
### 问题
### 原因
### 对策

## 我能想起来的案例

## 我能想起来的表述

## 对照知识库后的补充
- 遗漏观点：
- 遗漏案例：
- 遗漏角度：

## 暴露出的知识缺口
- [ ] 缺观点
- [ ] 缺原因
- [ ] 缺对策
- [ ] 缺案例
- [ ] 缺数据
- [ ] 缺规范表达

## 最终答题框架

## 下周重点收集
```

### 模式 D：真题复盘与方法库更新

做完真题后：
1. 对比用户答案与材料/参考思路；
2. 区分“专题知识缺口”和“方法缺口”；
3. 专题知识缺口回写专题库；
4. 只有跨主题可复用的方法才进入方法库；
5. 不因一次偶然失误创造新的“方法”。

方法卡应包含：适用题型、使用步骤、判断条件、常见误区、至少一个应用示例。

## 去重与链接规则

1. **单一权威版本**：同一案例/数据原则上只保存一份，其他专题用 `[[双向链接]]` 引用。
2. 新建文件前必须 Glob/Grep 搜索同义名称、简称和关键词。
3. 同义专题优先合并。例如“基层数字治理”和“数字化基层治理”不要无故分裂。
4. 原文摘录不是知识。优先转述为自己的结构化理解；必须保留原句时明确标注来源。
5. 不得虚构案例、数据、政策文件、出处、日期或原文链接。
6. 无法确认的信息标记 `[待核实]`，不要猜。

## 半自动化边界

### AI 应主动完成
- 元数据整理；
- 主题标签候选；
- 文章结构拆解；
- 观点/问题/原因/对策候选；
- 案例、数据、权威表述、表达候选；
- 搜索现有专题并建议关联；
- 去重与双向链接；
- 每周对照与知识缺口统计；
- 维护 Markdown 格式一致性。

### 用户必须参与
- 判断文章是否真正值得精读；
- 确认一句话主旨是否准确；
- 写或修改“我的转化”；
- 每周先做闭卷输出；
- 真题先独立作答；
- 决定真正需要记忆的表达。

不要为了“自动化完整”而跳过这些学习动作。

## 写作与格式

- Markdown 使用 UTF-8。
- 标题层级稳定，避免无意义深层嵌套。
- 有序列表连续，不在每项之间使用会导致渲染重置的错误结构。
- 标签和链接命名保持统一。
- 不堆砌标签：通常 2–5 个主题关联足够。
- 原文长段落不要整段复制；以结构化提炼为主。

## 用户常用指令示例

- “整理今天的官媒文章，先帮我筛选值得精读的。”
- “精读这篇文章并沉淀到遴选知识库，我自己写‘我的转化’。”
- “把今天三篇文章整理完，更新专题库，但素材库只收高复用素材。”
- “做本周重组，主题选基层治理，先给我留闭卷区，不要先展示知识库答案。”
- “我已经完成闭卷输出，帮我对照专题库找知识缺口。”
- “复盘这道真题，并判断哪些内容应该进入方法库。”
